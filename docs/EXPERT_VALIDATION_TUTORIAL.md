# Пошаговая инструкция эксперту: валидация извлечения изменений в НПА

Версия: 1.0  
Репозиторий: `lawful-good-project/legal-agent-harness`  
Целевой датасет: `lawful-good-project/legal-agent-calibrations`

> Это учебная проверка качества извлечения, а не юридическая консультация. Эксперт самостоятельно сверяет результат с официальным источником.

## 1. Что понадобится

Эксперту нужны только:

1. установленный [OpenCode](https://opencode.ai/);
2. доступ к рабочему каталогу `legal-agent-harness`;
3. один нормативно-правовой документ в формате PDF, TXT, HTML, DOCX или RTF;
4. новый Hugging Face token с правом записи в датасет `lawful-good-project/legal-agent-calibrations`.

**Никогда не вставляйте токен в обычный текстовый чат, Git, комментарии, скриншоты или журналы.** Вводите его только в защищённое поле локальной формы. Если токен уже был опубликован, сначала отзовите его на Hugging Face и создайте новый.

## 2. Где находится агент

В репозитории уже есть OpenCode skill:

```text
.opencode/skills/legal-agent-calibration-harness/SKILL.md
```

Откройте проект именно из каталога репозитория:

```powershell
cd C:\путь\к\legal-agent-harness
opencode .
```

После запуска OpenCode агент увидит локальный skill. Если skill не подхватился автоматически, в чат OpenCode вставьте промпт из раздела 4 этой инструкции.

В репозитории также находятся исполняемые части конвейера:

```text
scripts/validation_web.py          # локальная интерактивная форма
scripts/launch_validation_app.py   # CLI для одного документа
src/legal_agent_harness/validation_app.py  # извлечение, граф, review и публикация
schemas/extraction_graph.json      # схема графа
schemas/expert_review.json         # схема экспертной оценки
docs/VALIDATION_STEP_BY_STEP.md    # краткая памятка
```

## 3. Подготовка окружения

В PowerShell выполните:

```powershell
cd C:\путь\к\legal-agent-harness
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pytest -q
```

Успешный результат тестов должен завершаться строкой вида:

```text
37 passed
```

Если PowerShell запрещает активацию окружения, выполните один раз:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Затем повторите активацию `.\.venv\Scripts\Activate.ps1`.

## 4. Промпт для OpenCode

Скопируйте в чат OpenCode следующий промпт целиком:

```text
Ты — оператор конвейера экспертной валидации извлечения изменений из нормативно-правовых актов в репозитории legal-agent-harness.

Твоя задача — сам пройти весь конвейер, а от эксперта запросить только необходимые действия:
1) открыть локальную форму;
2) ввести HF API token только в защищённое поле формы;
3) выбрать нормативный документ;
4) проверить показанные ключевые поля и направленный граф;
5) выставить оценку 0–10 и при желании написать комментарий.

Обязательные правила безопасности:
- Не проси эксперта отправлять HF token в чат.
- Не печатай, не логируй и не сохраняй токен в файлы, переменные проекта или Git.
- Не загружай в Git полный текст документа, персональные данные и секреты.
- Если токен уже был опубликован, остановись и попроси отозвать его.
- Результат — учебная проверка качества извлечения, не юридическая консультация.

Сначала проверь, что текущий каталог — legal-agent-harness, и прочитай:
- AGENTS.md;
- README-VALIDATION.md;
- docs/EXPERT_VALIDATION_TUTORIAL.md;
- docs/AMENDMENT-EXTRACTION.md.

Затем:
1. Проверь наличие Python и запусти тесты: python -m pytest -q.
2. Запусти локальную форму командой:
   python scripts/validation_web.py 8000
3. Открой в браузере http://127.0.0.1:8000.
4. Попроси эксперта ввести HF token только в поле формы, выбрать файл PDF/TXT/HTML/DOCX/RTF, указать орган и юрисдикцию, выбрать оценку 0–10 и добавить комментарий по желанию.
5. После отправки объясни эксперту результат:
   - records — извлечённые ключи: norm_id, predicate, subject, object, effective_from, effective_to, change_description, confidence, coordinate;
   - nodes — узлы графа;
   - edges — причинно-следственные связи «изменяющий акт → изменённая норма»;
   - sha256 — контрольная сумма файла, а не полный текст.
6. Попроси эксперта сверить номер статьи, тип изменения, дату, координату, акт-источник и причинную связь с официальным документом.
7. После подтверждения формы результат должен сохраниться в append-only журнал validation/reviews.jsonl и отправиться в lawful-good-project/legal-agent-calibrations. При ошибке публикации не повторяй токен в сообщении: сообщи только тип ошибки и сохрани локальный review.
8. Покажи эксперту, где сохранена локальная запись, но не показывай и не выводи HF token.

Не утверждай, что результат юридически верен. Не выставляй оценку вместо эксперта. Не завершай работу до того, как эксперт сам выберет score от 0 до 10.
```

## 5. Запуск конвейера агентом

После вставки промпта агент должен запустить:

```powershell
python scripts/validation_web.py 8000
```

Откроется локальный сервер только на `127.0.0.1`. Перейдите в браузере на:

```text
http://127.0.0.1:8000
```

Если порт 8000 занят, используйте другой:

```powershell
python scripts/validation_web.py 8765
```

и откройте `http://127.0.0.1:8765`.

Остановить сервер можно в окне терминала сочетанием `Ctrl+C`.

## 6. Что сделать в форме

### Поле HF API token

Вставьте новый токен только в поле типа password. Форма использует его для запроса к Hugging Face и не записывает его в `validation/reviews.jsonl`.

### Орган и юрисдикция

Заполните, например:

```text
Орган: Государственная Дума ФС РФ
Юрисдикция: RU
```

### Документ

Выберите файл нормативного акта. Поддерживаются:

- `.pdf` — best-effort извлечение без OCR;
- `.txt`;
- `.html`, `.htm`;
- `.docx`;
- `.rtf`.

Ограничение размера — 20 МБ. Если PDF является сканом без текстового слоя, результат может быть неполным; такой результат следует оценивать соответственно или сначала предоставить OCR-версию.

### Оценка

Выберите целое число:

| Балл | Значение |
|---:|---|
| 0 | агент полностью не справился |
| 1–3 | извлечение в основном непригодно |
| 4–6 | обнаружена часть изменений, есть существенные ошибки |
| 7–8 | основная структура верна, есть отдельные ошибки |
| 9 | почти полное соответствие, есть незначительные замечания |
| 10 | полностью справился по проверенным полям и связям |

В комментарии укажите конкретные ошибки, например:

```text
Неверно определён predicate: указано «изменена», а в акте «дополнена».
Дата вступления в силу верна. Статья 1252 определена верно.
```

## 7. Что именно проверяет эксперт

Проверяйте по официальному источнику:

1. `norm_id` — идентификатор статьи/нормы;
2. `predicate` — один из канонических типов: `изменена`, `дополнена`, `введена`, `изложена_в_новой_редакции`, `признана_утратившей_силу`, `исключена`, `уточнена`;
3. `subject` — какая норма изменена;
4. `object` — каким актом внесено изменение;
5. `effective_from` и `effective_to` — даты действия редакции;
6. `change_description` — краткое описание без подмены текста нормы;
7. `confidence` — соответствует ли уверенность фактическому качеству;
8. `coordinate` — статья, пункт, абзац или другая точная координата;
9. `edges` — действительно ли направленная связь идёт от изменяющего акта к изменённой норме;
10. отсутствие лишних узлов и связей.

Автоматическое совпадение или высокая `confidence` не заменяют экспертную проверку.

## 8. Где сохраняется результат

Локальный append-only журнал:

```text
validation/reviews.jsonl
```

Публичная запись содержит только необходимые поля, хэш файла, граф, извлечённые записи, оценку и комментарий. Полный исходный текст документа, токен и персональные данные туда не должны попадать.

Целевой датасет:

```text
https://huggingface.co/datasets/lawful-good-project/legal-agent-calibrations
```

Если Hugging Face недоступен или токен не имеет права записи, локальная запись всё равно должна сохраниться. Не вставляйте токен повторно в чат и не добавляйте его в командную строку.

## 9. Альтернативный CLI-режим

Если интерактивная форма недоступна, можно обработать документ без веб-интерфейса:

```powershell
python scripts/launch_validation_app.py акт.pdf `
  --authority "Государственная Дума ФС РФ" `
  --jurisdiction RU
```

Команда выведет граф и записи. После отдельной проверки экспертом допустимо добавить оценку:

```powershell
python scripts/launch_validation_app.py акт.pdf `
  --authority "Государственная Дума ФС РФ" `
  --jurisdiction RU `
  --score 8 `
  --comments "Проверены статья, дата и тип изменения"
```

Для обычной экспертной работы предпочтительна веб-форма: она не требует передавать токен через аргументы командной строки.

## 10. Завершение задания

Задание считается выполненным, когда:

- эксперт самостоятельно проверил `records` и `edges` по официальному источнику;
- эксперт выбрал оценку от 0 до 10;
- комментарий добавлен при наличии замечаний;
- локальная запись появилась в `validation/reviews.jsonl`;
- агент сообщил статус публикации без раскрытия токена;
- тесты проекта проходят;
- в Git не добавлены исходный документ, токен или полный сырой текст.

Перед закрытием работы проверьте:

```powershell
git status --short
git diff --check
```

Не выполняйте `git add` для `validation/reviews.jsonl`, загруженных документов или файлов с секретами.

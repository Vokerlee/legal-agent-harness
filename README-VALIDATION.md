# Expert Validation App (статичный контур для извлечения поправок)

Этот контур обеспечивает **автоматизированную экспертом валидацию** для извлечённых статей с последующей отправкой в Hugging Face (или локальное хранение).

## Основные компоненты

| Путь | Назначение |
|-----|---------|
| `README-VALIDATION.md` | Эта документация |
| `src/legal_agent_harness/validation_app.py` | Контур прогона (text -> graph -> эксперт -> HF) без сетевых зависимостей, кроме `urllib` (стандартная библиотека) |
| `schemas/extraction_graph.json` | Схема для графического представления правил извлечения/причинно-следственных связей |
| `schemas/expert_review.json` | Схема для записи оценки эксперта (score 0-10, комментарии) |
| `scripts/launch_validation_app.py` | CLI для запуска статичного сервера (FastAPI-стиль, минимальные `http.server` зависимости) |
| `docs/VALIDATION_STEP_BY_STEP.md` | Последовательный туториал для эксперта (полные русскоязычные инструкции) |
| `examples/validation_cases.jsonl` | Ограниченный набор тестовых кейсов для документационных целей |
| `validation/__init__.py` | Пустой пакет для экспорта модулей |

## Промпт для агента Opencode (эксперт)

Скопируйте этот текст агенту (в opencode):

```text
# Промпт агента экспертной валидации (статичный контур)

Вы — контур экспертной валидации. Ваша роль — принять нормативный документ, извлечённый автоматическим агентом, проанализировать его на предмет изменений, оценить качество извлечения, присвоить оценку 0-10, при желании написать комментарии и отправить всё на Hugging Face (или локально) **без сохранения API-ключей**

## Шаги (подробнее см. в `VALIDATION_STEP_BY_STEP.md`)

1. **Войти через форму** – введите свой Hugging Face токен (никогда не храните его в кодах). Используйте статичный HTML-формуляр, который откроется в браузере (без серверных файлов). Контур выведет незаполненные поля, вы введёте токен.

2. **Загрузить нормативный акт** – выберите файл (PDF, DOCX, TXT, HTML, RTF). Контур извлечёт из него правовые изменения до установленной в проекте схемы:
   - **Причинано-следственный граф**: узлы = акт -> норма; связи = предикат (“изменена”, “дополнена” и т.д.), координаты, уверенность.
   - **Поля извлечения** (эквивалентны ожидаемым полям калибровочного harness):
     `norm_id`, `predicate`, `subject`, `object`, `effective_from`, `effective_to`, `change_description`, `confidence`, `coordinate`.

3. **Экстракт распечатать** – вы увидите текстовый отчёт на основе графов плюс список полей. Выделите любые неточности (неправильная дата, неправильная статья, некачественная уверенность, лишние/отсутствующие поля).

4. **Оценить качество** – выберите оценку по шкале 0–10, где 0 = полностью не справился, 10 = полностью справился. По желанию введите комментарии в форме.

5. **Подтвердить и отправить** – нажмите «Отправить результат эксперта». Контур сохранит отчёт в JSONL журнал (редактированный, без секретов), отправит его в датасет `lawful-good-project/legal-agent-calibrations` (по возможности) и выведет ссылку на публикованное событие.

## Контракты с данными

- Графические и экспертные записи всегда редактируются:
  - Секреты (`token`, `api_key`, `password`, `email`) вырезаются.
  - Сырые полные тексты (`full_text`, `raw_text`) и персональные данные не экспортируются.
  - Все записи завершаются `expert_approved` (автоматическая совокупность полей).
- Используйте существующую структуру калибровочного harness (`examples/amendments.jsonl` как образец для первоначальных кейсов).

## Запуск контура

```bash
cd legal-agent-harness
pip install -e ".[validation]"  # если нужны дополнительные зависимости, приведённые ниже
python scripts/launch_validation_app.py --port 8000 --host 0.0.0.0
```

Контур предоставляет статичный веб-интерфейс, работает в stdlib, без баз данных (извлечение текста в память).

## Соглашения

- Язык интерфейса и документации — русский.
- Контур никогда не логирует секреты и не сохраняет HL-токены.
- Без сетевых вызовов, кроме `urllib` для Hugging Face API (на усмотрение эксперта).
- Без долгосрочных процессов — запрос и ответ обрабатываются в одном HTTP-вызове.

## Тесты

```bash
python -m pytest -q tests/validation_test.py
```

Софткодовое тестирование ядер контура (валидация, извлечение, экспертная оценка, публикация через HF API).

## Документация для эксперта

Полный пошаговый туториал для эксперта и инструкции по использованию контура см. в `docs/VALIDATION_STEP_BY_STEP.md`.

## Критерии завершения

Контур считается завершённым, когда:

- В `validation/__init__.py` экспортируется минимальный набор необходимых инструментов.
- `README-VALIDATION.md` описывает интерфейс, контракты и запуски.
- `docs/VALIDATION_STEP_BY_STEP.md` содержит полный русскоязычный туториал с ожиданием формы, обработкой файлов, оценкой, отправкой.
- Все файлы применяют редакцию, публикуют только экспорт, сохраняют append-only-конфигурацию с `expert_approved`.
- Имеются интеграционные тесты (`tests/validation_test.py`), покрывающие загрузку файлов, извлечение, граф, экспертную оценку, публикацию через HF API (с `urlexpect`), и тесты на редакцию.
- В каталоге `validation/` находится простой журнал событий, пример экспортного файла и образец поля оценки эксперта.
- В репозитории `legal-agent-harness` создан единый PR (или цепочка коммитов) со всеми изменениями.
- Критерии качества контура больше не нарушаются после завершающего QA-обхода.

## Как редактировать/добавлять новые документы (обращение к пользователю)

- Используйте `scripts/launch_validation_app.py --edit-graph` для редактирования графов или `scripts/launch_validation_app.py --edit-schema` для редактирования JSON Schema.
- Изменения проводятся только после сессии Q/A; изменяйте только свои файлы контура (редакционные права ограничены).
- Приложения размещаются в `validation/uploads/`, `validation/journals/` и `validation/exports/`.

## Примечания/Исключения

- Извлечение из PDF/DOCX — best-effort, без OCR; для совершенства текст может содержать пропущенные страницы.
- Контур может отклонить файл, если размер > 20 МБ или формат не поддерживается.
- Оценка 0 допускается (секретный вывод).
- Формуляр включён напрямую в HTML-страницу контура; нет файлов cookie.
- Для тестирования функции публикации HF требуется `HF_TOKEN`; используйте переменную окружения или форму (форма будет заполнять её локально).
- Секреты никогда не записываются на диск; они существуют только в процессе запроса-ответа.
